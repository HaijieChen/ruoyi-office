# 表单数据源设计器 Schema 驱动配置设计

日期：2026-07-18

## 1. 背景

动态表单中的 `RemoteDataSourceSelect` 当前只通过精简接口获得数据源名称和标识。属性面板中的请求参数绑定、结果字段联动、显示字段和值字段全部依赖手工输入，设计人员无法知道已发布数据源实际声明了哪些参数和结果字段，也无法看到字段的中文含义。

后端在表单保存或流程发布时已经按已发布 Schema 校验参数名、结果字段和目标字段。允许设计器手工输入 Schema 之外的名字不会提供扩展能力，只会产生稍后必然被后端拒绝的无效配置。

## 2. 目标

- 让设计人员只选择已发布 Schema 中真实存在的参数和结果字段。
- 每个技术字段同时展示中文名称、技术字段名、数据类型和必填属性。
- 让绑定表达式和目标字段从当前表单及允许的系统上下文中选择。
- 切换数据源时不保留新数据源无法识别的陈旧配置。
- 在表单设计器中提供明确的数据源管理入口。
- 继续保证运行端和普通表单设计端无法读取 SQL、平台 API 配置或其他敏感实现信息。

## 3. 非目标

- 不改变数据源执行、缓存、脱敏和租户隔离逻辑。
- 不允许在表单设计器中创建或编辑 SQL。
- 不支持输入 Schema 之外的临时字段路径。
- 不修改第三方 `@form-create/antd-designer` 包源码。

## 4. 交互设计

### 4.1 数据源选择

“数据源标识”继续使用可搜索下拉框，选项显示 `中文名称（技术标识）`。右侧增加两个操作：

- “管理数据源”：在新的应用页签打开 `流程中心 > 流程设置 > 表单数据源`，保留当前未保存表单。
- “刷新”：重新获取数据源精简列表和当前数据源的已发布元数据。

数据源没有已发布版本时不出现在选择列表中。已选数据源被停用或取消发布时，保留原值用于诊断，但配置区禁用并显示明确提示。

### 4.2 请求参数绑定

请求参数表格的“数据源参数名”改为严格下拉：

- 仅列出已发布参数 Schema 中允许客户端绑定的参数。
- 已由服务端注入的 `tenantId`、`userId`、`deptId`、`companyId` 显示在“系统自动注入”说明中，不允许加入绑定表格。
- 已用于搜索、页码或每页条数控制的参数不再允许重复绑定。
- 已在其他绑定行选择的参数在后续行中禁用，避免重复键覆盖。

选项格式示例：`主体公司（selectedCompanyId · LONG · 必填）`。

“绑定表达式”改为严格下拉，分为三组：

- 当前表单：递归枚举当前表单可引用字段，显示 `主体公司（FORM.companyId）`。
- 当前用户：`当前用户（USER.id）`、`所属部门（USER.deptId）`、`所属公司（USER.companyId）`。
- 当前流程：`流程定义标识（PROCESS.definitionKey）`、`流程实例编号（PROCESS.instanceId）`。

不提供手工输入。表单中的嵌套字段通过递归字段解析进入下拉列表。

### 4.3 结果字段联动

“结果字段路径”改为严格下拉，仅列出已发布结果 Schema 字段。选项格式示例：`客商名称（partyName · STRING）`。

“目标表单字段”改为严格下拉，显示 `客商名称（customerName）`。候选字段递归来自当前表单，并排除：

- 当前数据源选择组件自身；
- 其他 `RemoteDataSourceSelect` 字段；
- 没有稳定 `field` 的展示和布局组件。

同一个结果字段只能配置一次。没有映射时显示“点击添加结果字段映射”，不再使用只有“暂无数据”的空表格。

### 4.4 其他 Schema 相关属性

以下属性同步改为严格下拉，避免在其他位置继续手工输入无效字段：

- 显示字段、值字段：来自结果 Schema；
- 搜索参数、页码参数、每页条数参数：来自参数 Schema；
- 依赖字段、快照存储字段：来自当前表单字段。

分页参数仅在启用分页后展示。搜索、页码和每页条数参数之间不能重复。

### 4.5 切换数据源

存在已有绑定或映射时切换数据源，先提示“切换数据源将清除不兼容配置”。确认后：

- 保留在新 Schema 中仍存在且用途未冲突的配置；
- 清除不存在或用途冲突的参数绑定、结果映射和控制参数；
- 重新使用新数据源发布版本的显示字段、值字段和分页默认值。

取消切换时不修改当前配置。

## 5. Schema 中文名称

参数 Schema 和结果 Schema 的字段结构增加可持久化的 `label`：

```json
{
  "name": "partyName",
  "label": "客商名称",
  "type": "STRING",
  "required": true
}
```

规则如下：

- 新建或保存数据源草稿时，`label` 必填，去除首尾空白，长度为 1 至 64 个字符。
- `name` 仍是唯一技术标识，中文名称不参与执行、投影或参数绑定。
- 脱敏字段继续保留 `mask`，新增 `label` 不改变运行结果。
- 历史版本读取时兼容缺少 `label` 的 Schema，设计器临时回退显示技术字段名。
- 当前所有已发布数据源通过正常的“新建草稿并发布”路径补齐中文名称，不直接改写历史版本。

Schema 使用 JSON 存储，因此不需要新增数据库列。

## 6. 后端接口与安全边界

新增只读接口：

```text
GET /bpm/form-data-source/published-metadata?code={code}
```

接口要求 `bpm:form-data-source:query` 权限，只返回当前租户下已启用数据源的已发布元数据：

- `id`、`name`、`code`、`type`、`publishedVersion`；
- `parameterFields`、`resultFields`；
- `labelField`、`valueField`、`pageable`。

接口绝不返回：

- `sourceConfig`；
- SQL；
- 平台 API 路径或请求配置；
- 草稿和历史版本 Schema；
- 运行数据。

后端保存数据源版本时校验 `label`，并继续使用现有字段名、类型、脱敏、引用和租户安全校验。表单发布校验仍是最终权威，前端下拉不能替代后端校验。

## 7. 前端结构

新增应用自有的 Schema 配置组件，不修改 `node_modules`：

- 已发布元数据加载器：按数据源标识加载、缓存和刷新元数据；
- Schema 选项转换器：生成包含中文名称、字段名、类型和必填状态的选项；
- 表单字段解析器：递归解析普通字段、子规则、表格列和控制规则；
- 参数绑定表格：两列严格下拉；
- 结果映射表格：两列严格下拉；
- 数据源属性编辑器：协调数据源切换、控制参数去重和旧配置清理。

这些组件通过明确的 props 和事件接收当前组件配置、当前表单规则及数据源元数据，不依赖第三方设计器的私有 DOM 结构。

## 8. 数据流

1. 打开表单设计器，加载已发布数据源精简列表。
2. 选中 `RemoteDataSourceSelect`，根据 `dataSourceCode` 请求已发布元数据。
3. 将参数 Schema、结果 Schema和当前表单规则转换为严格下拉选项。
4. 用户选择参数、绑定表达式、结果字段和目标字段。
5. 设计器仍按现有结构保存 `parameterBindings`、`outputMappings` 等 props，运行时数据结构不变。
6. 保存表单和发布流程时，后端继续执行现有联动校验。

## 9. 错误处理

- 元数据加载中：配置表格显示加载状态并禁止新增行。
- 元数据加载失败：显示“数据源字段加载失败，点击重试”，保留已有配置但禁止保存新的无依据选择。
- 数据源没有已发布版本：显示“请先发布数据源版本”。
- 现有配置引用已删除字段：对应行显示红色“字段已不存在”，保存前必须重新选择或删除。
- 当前表单目标字段被删除：映射行显示“目标字段已不存在”，保存前必须处理。
- 无参数或无结果字段：显示带原因的空状态，而不是笼统的“暂无数据”。

## 10. 兼容与迁移

- 已有表单配置的数据结构不变，无需批量改写表单 JSON。
- 合法的现有值在严格下拉中正常回显。
- 非法或过期值以错误状态回显，不静默删除；仅在用户确认切换数据源时清理。
- 当前已发布数据源逐一补齐 Schema 中文名称并发布新版本，旧版本保留用于审计。
- 运行端 `RemoteDataSourceSelect` 不需要修改配置协议。

## 11. 测试策略

### 11.1 后端

- 元数据接口只返回已启用数据源的已发布版本。
- 返回 Schema、标签字段和值字段，但不包含 `sourceConfig`、SQL 或 API 配置。
- 无权限、停用、无发布版本和跨租户访问均被拒绝或返回不存在。
- 新草稿缺少中文名称、中文名称过长或空白时保存失败。
- 增加 `label` 后现有执行、脱敏和联动校验保持通过。

### 11.2 前端单元测试

- Schema 字段转换为正确的中文选项文本。
- 系统注入参数和已占用控制参数不可被绑定。
- 当前表单字段递归解析完整，远程选择字段不进入回填目标候选。
- 切换数据源只保留兼容配置并清除无效配置。
- 不存在的历史字段显示错误状态。
- 参数、结果、目标和控制字段均不能输入下拉列表之外的值。

### 11.3 浏览器验收

在表单 49 的设计器中选择 `oa_available_seals` 和 `crm_customers` 验证：

- 请求参数名下拉显示中文名称、字段名、类型和必填状态；
- 绑定表达式可选择当前表单、用户和流程字段；
- 结果字段下拉显示已发布返回字段及中文名称；
- 目标字段下拉显示当前表单中文标题和字段名；
- 显示字段、值字段、搜索和分页参数均为严格下拉；
- “管理数据源”可在新应用页签打开表单数据源管理；
- 页面不出现 SQL、API 配置或任意手工字段输入入口。

## 12. 验收标准

- 设计人员不需要查看 SQL、接口文档或数据库即可完成数据源组件配置。
- 所有可配置字段均来自已发布 Schema 或当前表单的可枚举字段。
- 所有字段选项均具有中文名称；技术字段名仍可见以便排查。
- 无法通过界面产生 Schema 不存在的参数名或结果字段。
- 保存后的配置继续兼容现有运行时和流程发布校验。
- 安全元数据接口不泄露数据源实现配置。
