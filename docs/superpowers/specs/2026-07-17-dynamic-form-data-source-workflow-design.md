# OA 动态表单数据源联动与流程设计

## 1. 目标

根据 `docs/OA流程优化-318（合同用印流程变动）.xlsx` 配置 OA 表单和审批流程，同时把表单中的数据联动抽象为通用能力。

本次交付包括：

- 当前平台数据库的只读 SQL 数据源管理；
- 动态表单组件绑定数据源和字段联动；
- 工作簿涉及的动态表单配置；
- 8 个简易流程模型和 7 个 BPMN 流程模型；
- 流程字段权限、条件、办理节点、定时事件、触发器和子流程关系；
- 发布前校验、审计和生产验收。

审批人不在本次设计中写死。流程图绘制完成后，由平台管理员在设计器中设置各节点审批人。

## 2. 职责边界

### 2.1 动态表单负责

- 字段定义、默认值、必填、只读和条件显隐；
- 数据源选择、查询参数绑定和选项加载；
- 上下游组件联动、选中记录映射和字段回填；
- 选择并记录前置流程、客户、员工、公司、印章等业务数据；
- 将表单数据作为流程变量提交给 BPMN。

### 2.2 流程设计器负责

- 发起条件和前置流程校验；
- 审批、办理、会签、条件分支和并行汇聚；
- 延迟器、定时事件、触发器和子流程；
- 审批后归档、状态更新和通知；
- 合同结束日前 30、15、7 天提醒；
- 流程异常、重试和操作轨迹。

### 2.3 明确不做

- 不修改 Flowable/BPMN 引擎能力；
- 不在代码中写死审批人；
- 不为公司印章、前置流程、客户地址分别开发不可复用的专用表单组件；
- 不允许浏览器获取或执行 SQL；
- 不连接当前平台数据库以外的业务数据库。

## 3. 总体架构

```text
数据源管理
  ├─ 数据字典
  ├─ 平台 API
  └─ 当前平台数据库只读 SQL
          ↓
动态表单设计器
  ├─ 组件配置
  ├─ 参数绑定
  ├─ 返回值映射
  └─ 联动规则
          ↓
表单运行时
  ├─ 加载选项
  ├─ 回填字段
  ├─ 校验依赖
  └─ 提交流程变量
          ↓
简易流程设计器 / BPMN 流程设计器
  ├─ 审批与办理
  ├─ 分支与会签
  ├─ 定时与触发器
  └─ 子流程编排
```

数据源定义、表单组件和联动规则相互解耦。一个数据源可被多个表单复用，一个组件可切换不同数据源，联动关系通过配置表达式建立。

## 4. SQL 数据源设计

### 4.1 数据模型

新增三个配置与审计实体：

1. `bpm_form_data_source`
   - 数据源名称、编码、类型、启停状态；
   - 当前已发布版本；
   - 创建人、修改人、租户和时间字段。
2. `bpm_form_data_source_version`
   - 数据源编码和版本号；
   - 参数化 SQL 模板；
   - 参数、返回字段和数据类型定义；
   - 标签字段、值字段、分页、最大行数、超时和缓存配置；
   - 草稿、已发布、已停用状态。
3. `bpm_form_data_source_log`
   - 数据源编码、版本和调用场景；
   - 操作用户、租户、表单和流程实例；
   - 参数摘要、返回行数、耗时和执行结果；
   - SQL 模板标识，不记录敏感返回数据。

已发布版本不可原地修改。修改数据源时创建新草稿版本，校验和试运行通过后再发布。运行中的旧流程保留原表单值，不依赖数据源重放。

### 4.2 参数化查询

SQL 使用命名参数：

```sql
SELECT id, seal_name, seal_type, keeper_id, keeper_name
FROM oa_seal
WHERE company_id = :companyId
  AND status = 0
  AND deleted = 0
  AND tenant_id = :tenantId
ORDER BY sort, id
```

参数来源支持：

- 固定值；
- 当前表单字段，例如 `${form.companyId}`；
- 当前用户、部门、公司和租户；
- 当前流程变量；
- 分页参数和搜索关键字。

平台上下文自动提供 `tenantId`、`userId`、`deptId`、`companyId` 和用户可访问部门集合。数据源发布校验要求涉及租户表的 SQL 使用租户参数；需要数据权限的数据源必须声明并使用相应上下文参数。

### 4.3 安全约束

- 使用当前平台数据库的独立只读连接；
- 只允许单条 `SELECT` 或 `WITH ... SELECT`；
- 拒绝多语句、SQL 注释、DDL、DML、存储过程、文件操作和管理命令；
- 所有运行参数通过预编译语句绑定，禁止字符串拼接；
- 服务端解析并验证 SQL，浏览器仅提交数据源编码和参数；
- 单次查询默认最多 200 行、最长 3 秒，管理员可在更严格范围内调整；
- 分页数据源必须声明分页字段和稳定排序；
- 可对返回字段配置隐藏或脱敏；
- 试运行和正式执行均写审计日志；
- 已被已发布表单引用的数据源不得直接删除，只能停用新调用。

## 5. 动态表单组件与联动

### 5.1 通用数据源组件能力

选择类组件统一支持：

- 单选、多选、树形选择、弹窗表格和分页搜索；
- `dataSourceCode` 引用已发布数据源；
- 标签字段、值字段和显示列配置；
- 固定参数、表单字段和上下文参数绑定；
- 初始化、字段变化和手动刷新三种加载方式；
- 选中记录后将多个属性映射到其他字段；
- 编辑历史单据时按已保存的标签和值回显。

示例：

```json
{
  "field": "sealIds",
  "component": "RemoteSelect",
  "multiple": true,
  "dataSourceCode": "oa_available_seals",
  "params": {
    "companyId": "${form.companyId}"
  },
  "mapping": {
    "label": "sealName",
    "value": "id"
  },
  "dependencies": ["companyId"],
  "onDependencyChange": "clear-and-reload"
}
```

### 5.2 联动规则

联动引擎支持：

- 上游字段变化后重新查询下游数据源；
- 按规则清空、保留或重新校验下游值；
- 单字段和多字段参数组合；
- 选择一条或多条记录后回填多个字段；
- 条件显示、隐藏、必填、只读、禁用和计算值；
- 表单加载时按依赖顺序执行；
- 发布前检测循环依赖、缺失参数、错误映射和不存在的数据源；
- 查询失败时保留不相关字段，显示可重试的明确错误；
- 历史单据不因数据源记录停用而丢失显示值。

### 5.3 典型配置

公司与印章联动：

```text
主体公司字段 companyId
  → 作为 oa_available_seals.companyId 参数
  → 重新加载印章多选字段 sealIds
  → 选中后回填 sealNames、sealTypes、keeperIds
```

前置流程联动：

```text
文件类型 documentType
  → 决定允许选择的前置流程类型
  → 查询已审批通过的流程实例
  → 回填 preProcessInstanceId、preBusinessKey、preProcessSummary
```

客户地址联动：

```text
客户 customerId
  → 查询客户档案
  → 回填默认邮寄地址 mailingAddress
  → 本次地址允许修改，但不反向修改客户档案
```

## 6. 表单与流程模型清单

### 6.1 简易流程设计器：8 个

| 流程 | 主要节点 | 选择理由 |
| --- | --- | --- |
| 入职申请 | 发起、部门主管、总经理、实际入职办理、员工档案触发器 | 顺序审批和结束触发器即可表达 |
| 采购申请 | 发起、部门主管、总经理、财务负责人、采购办理 | 金额路线可用条件分支 |
| 普通用印 | 发起、部门主管、财务负责人、用印办理、归档触发器 | 顺序审批、办理和触发器即可表达 |
| 付款申请 | 发起、业务负责人、财务负责人、总经理、出纳办理 | 前置单据校验和条件审批可由现有节点表达 |
| 费用报销 | 发起、业务负责人、财务负责人、总经理、出纳办理、转付通知 | 条件分支和通知触发器即可表达 |
| 返点比例审批 | 发起、渠道总监、总经理、规则生效触发器 | 顺序审批和结束触发器即可表达 |
| 充值申请 | 发起、部门负责人、渠道总监、财务确认、状态触发器 | 条件审批和办理节点即可表达 |
| 退款/转充 | 发起、运营专员、财务、渠道总监、大额条件审批、执行办理 | 按类型和金额使用条件分支 |

审批人全部保留为待配置。表格中的角色名称用于标识节点职责，不绑定具体用户。

### 6.2 BPMN 流程设计器：7 个

| 流程 | 主要编排 | 选择理由 |
| --- | --- | --- |
| 离职申请 | 主管确认后并行进入交接人、IT、行政、财务会签，汇聚后 HR 结案 | 需要明确的并行会签和汇聚闭环 |
| 业务合同审批 | 前置流程校验、业务主管、法务、财务、总经理、用印、归档、到期提醒 | 包含跨流程校验和多个定时事件 |
| 员工劳动合同 | 入职流程校验、部门主管、财务、用印、归档、到期提醒 | 包含前置流程和多个定时事件 |
| 开票申请 | 业务、财务审批、开票办理、等待到款回单、未结案提醒 | 包含办理后的事件等待和持续提醒 |
| API 开票申请 | API 消息发起、财务办理、结果回传 | 包含外部消息触发和回传 |
| 到款认领/确认 | 流水导入、自动匹配、多笔认领、财务确认、错误撤销 | 包含批量关联、确认后生效和撤销路径 |
| 充值业务总编排 | 串联合同、返点、充值、到款和退款/转充子流程 | 负责多个独立流程间的状态编排 |

业务表单与流程模型不是一一对应。充值业务总编排是父流程，返点审批、充值申请和退款/转充仍是可独立发起的简易流程；充值合同复用业务合同审批能力，到款确认复用到款认领流程。

## 7. BPMN 配置原则

- 不修改现有 BPMN 引擎代码；
- 使用平台已有审批、办理、会签、条件、延迟、触发器和子流程能力；
- 流程图绘制完成后由管理员配置审批人；
- 表单字段权限按节点配置，执行后字段只允许对应办理节点编辑；
- 未配置审批人的模型不得发布或发起；
- 前置流程是否合法由流程发起校验负责，表单仅负责选择并提交引用；
- 归档、状态更新和提醒使用现有触发器或服务任务配置；
- 业务合同和劳动合同使用结束日前 30、15、7 天提醒；
- 已经过期的提醒节点不补发，仍未到期的节点继续创建；
- 流程图中的角色名称稳定，具体人员配置可按公司调整。

## 8. 发布与兼容

发布顺序：

```text
数据源配置并发布
  → 动态表单配置并发布
  → 绘制简易/BPMN 流程草稿
  → 管理员配置审批人
  → 流程发布
  → 联调验收
```

兼容要求：

- 现有运行中流程继续使用原流程定义版本；
- 新表单和流程以新版本发布，不覆盖历史定义；
- 历史表单按已保存字段和值展示；
- 数据源停用只阻止新查询，不删除历史数据；
- 当前旧版 OA 用印业务单在新流程验收完成前保留；
- 切换后通过菜单和发起权限隐藏旧入口，不直接删除历史业务记录。

## 9. 错误处理

- 数据源缺少参数：表单字段显示缺少的上游字段，不发起查询；
- 数据源查询失败：展示数据源名称和重试操作，不清空其他已填字段；
- SQL 超时或超行数：服务端终止查询并记录审计日志；
- 数据权限不足：返回无权限提示，不泄露 SQL、表名或原始异常；
- 联动循环：发布校验失败并显示完整依赖链；
- 返回字段变化：新版本数据源发布前检查所有引用表单；
- 审批人未配置：流程禁止发布或发起并定位具体节点；
- BPMN 触发器失败：按现有引擎重试和异常处理机制执行，不新增旁路任务系统。

## 10. 测试与验收

### 10.1 数据源安全

- 允许单条参数化 `SELECT` 和 `WITH ... SELECT`；
- 拒绝注入、多语句、DDL、DML、注释和危险函数；
- 验证租户、用户、部门和公司数据权限；
- 验证查询超时、最大行数、分页和审计日志；
- 验证 SQL 不会返回给浏览器。

### 10.2 表单联动

- 单字段、多字段和三级依赖联动；
- 单选、多选、分页搜索和弹窗表格；
- 选中记录后多字段回填；
- 上游切换后的清空、保留和重新校验；
- 初始化顺序、编辑回显、停用记录回显；
- 空数据、无权限、超时和重试；
- 循环依赖和错误映射的发布拦截。

### 10.3 流程

- 8 个简易流程和 7 个 BPMN 流程均可创建草稿；
- 配置审批人后可发布并发起；
- 条件分支、并行会签、办理节点和子流程按图流转；
- 合同 30、15、7 天提醒按结束日期创建；
- 归档、状态更新和通知触发器正常执行；
- 未配置审批人、无效前置流程和必填执行字段可被拦截；
- 旧流程实例、旧表单和旧用印记录不受新版本影响。

## 11. 上线完成标准

- SQL 数据源可由授权管理员创建、试运行、发布、停用和审计；
- 动态表单组件可灵活绑定数据源并配置参数、映射和联动；
- 工作簿涉及的表单均完成配置；
- 15 个流程模型完成绘制，审批人节点清晰标记为待管理员配置；
- 管理员配置审批人后，全部流程通过端到端验收；
- 没有为 BPMN 引擎增加定制代码；
- 没有破坏现有运行中流程和历史数据。
