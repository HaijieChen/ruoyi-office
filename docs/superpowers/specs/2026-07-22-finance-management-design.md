# 财务管理模块设计

## 背景与范围

新增独立 Maven 模块 `yudao-module-finance`，用于管理企业银行到款数据及其商务认领流程。

本设计基于以下需求资料：

- `docs/财务需求/summary-财务系统需求与流程梳理-会议纪要.docx`
- `docs/财务需求/OA流程优化-318（合同用印流程变动）.xlsx`
- `docs/财务需求/OA表单-722.xlsx`

第一期目标是建立可审计的“银行到款记录 -> 商务单 -> 商务认领明细 -> 财务确认”闭环。财务负责导入和维护银行到款数据；商务人员负责认领；财务负责确认。出账导入不在“到款认领表”中定义，待提供出账模板后独立纳入。

## 领域模型

### 银行到款记录

银行到款记录是从银行流水导入的业务款，由财务人员维护，并作为待认领池中的最小金额来源。

字段以“到款认领表”为准：

- 到款流水号：系统自动生成，格式为 `RC-{YYYYMMDD}-{序号}`。
- 导入日期、导入人、银行账户。
- 交易日期、付款方名称、付款方账号、交易金额、摘要或附言、银行流水号。
- 认领状态、已认领金额、未认领金额。

银行流水号是防重复的唯一标识。未认领金额自动计算为交易金额减已认领金额；已认领金额仅在财务确认认领后更新。

认领状态：

- 待认领：尚无已确认的认领金额。
- 部分认领：已确认的认领金额小于交易金额。
- 完全认领：已确认的认领金额等于交易金额。
- 已关闭：财务人工关闭、不再允许认领。

### 商务单

商务单是新增的独立业务凭据，来源为 `OA表单-722.xlsx` 的“商务签单信息”。商务人员通过 Excel 批量导入商务签单明细，开票申请、到款认领和后续收入报表均以商务单明细作为收入结算口径。

主表字段：商务单 ID、导入日期、导入人、银行账户。商务单 ID 由系统自动生成；导入人默认为当前商务人员；银行账户记录公司收款账户，内容包含银行户名和银行账号。

明细字段：合同审批流程 ID、下单日期、产品名称、对接人、执行开始日、执行截止日、付款方名称、签单执行金额、折扣率、签单结算金额、摘要或附言。

字段规则：

- 合同审批流程 ID 后续应关联到对应合同审批流程；历史未在 OA 申请的合同允许暂不填写。
- 付款方名称为非必填，一个产品涉及多个开票主体时可留空。
- 折扣率为空时按 `0` 计算。
- 签单结算金额自动计算为 `签单执行金额 * (1 - 折扣率)`。
- 商务单明细的已开票金额、已回款金额、已退款金额和待核销金额由关联流程汇总，不允许人工直接改写。

状态：草稿、有效、已关闭。只有有效商务单明细可以被用于开票申请和到款认领。

### 认领单与认领明细

认领单由商务人员或充值人员创建，包含一条或多条认领明细。每条认领明细必须关联一笔银行到款记录和一张商务单，并记录本次核销金额。

认领明细字段：认领明细 ID、认领人、认领时间、认领状态、银行到款记录 ID、可认领金额、商务单 ID、应收金额、本次核销金额、备注。

认领状态：待财务确认、已确认、已驳回。驳回后的认领单由原商务人员修改后重新提交，审核意见与历史记录保留。

## 业务流程

1. 财务人员从银行流水 Excel 导入银行到款记录；每笔记录初始已认领金额为零、未认领金额等于交易金额、状态为待认领。
2. 商务人员创建或选择有效商务单。
3. 商务人员从待认领池选择一笔或多笔银行到款记录，并选择一张或多张商务单；为每个“到款记录—商务单”组合填写本次核销金额后提交。
4. 财务人员确认认领单：确认时更新相关到款记录的已认领金额、未认领金额和认领状态，并更新商务单的已核销金额；驳回时写入审核意见，双方金额不变。
5. 商务人员可修改被驳回的认领单后重新提交。

### 相关流程联动

- 开票申请必须选择商务单 ID；业务账期从所选商务单明细的执行截止日按 `YYYY-MM` 自动带出；开票金额不得超过该商务单明细的剩余可开票金额。
- 红冲发票申请必须关联前期已开票申请；红冲金额不得超过原开票申请的已开票金额。商务单已开票金额按“已开票金额 - 已确认红冲金额”计算。
- 到款认领明细可选择充值单 ID 或商务单 ID；选择商务单时，应收金额取商务签单信息中的签单结算金额，单次认领金额不得超过银行流水可认领金额和商务单待回款金额。
- 退款申请关联未认领到款或已确认到款认领单；商务单已回款金额按“已确认到款认领金额 - 已确认退款金额”计算。
- 财务报表至少包含商务签单明细表，并按商务单明细汇总签单结算金额、已开票金额、已回款金额和待开票/待回款余额。

## 约束与权限

- 认领金额必须大于零。
- 同一笔银行到款记录可认领到多张商务单；同一张商务单也可由多笔银行到款记录认领。
- 同一笔银行到款记录可被多次、部分认领，但已确认的核销金额累计不得超过交易金额；同一商务单累计核销金额不得超过其应收金额。
- 同一商务单明细累计开票金额不得超过签单结算金额；红冲后释放可开票余额。
- 同一商务单明细累计确认回款金额扣减退款后不得超过签单结算金额。
- 提交时必须关联有效商务单，且至少包含一条认领明细。
- 财务确认时必须在事务内重新校验到款记录剩余可认领金额和商务单剩余应收金额，避免并发超额认领。
- 财务人员拥有银行到款导入、维护、全部认领查询和确认权限。
- 商务人员只能维护本人负责的商务单，创建、提交及修改本人认领单。
- 管理员拥有全量查询与配置权限。

## 界面与接口范围

第一期完整闭环的管理后台页面：银行到款记录、商务单导入与明细、我的认领、待确认认领、认领详情、商务签单明细报表。

第一期银行到款导入模板以 `docs/财务需求/OA流程优化-318（合同用印流程变动）.xlsx` 中的“到款认领表”为唯一来源，不另行设计模板。实现时按其银行流水明细列进行导入、逐行校验和错误结果反馈。自动银行接口、收费系统接口仅保留后续扩展边界。

## 实现方式

后端遵循现有模块模式，包含 Controller、Service、Mapper、数据对象、请求/响应 VO、权限点和数据库迁移脚本。认领明细使用独立表保存认领单、银行到款记录、商务单和核销金额关系，以支持多对多核销。

测试至少覆盖：银行流水导入校验和重复流水号拦截、商务单 Excel 导入与签单结算金额计算、商务单和认领单校验、多对多部分认领、到款金额及商务单应收金额的双向超额拦截、开票与红冲金额汇总、退款扣减已回款金额、驳回重提、确认后的到款状态变化，以及权限隔离。

## 非目标

第一期不包含：银行或收费系统实时接口、自动匹配、会计凭证生成、合同用印流程改造、百度 API 自动充值或银行 API 对接。这些能力待字段、接口和规则明确后分别设计。

## 已知待定项

- 商务单合同审批流程 ID 后续需要从文本过渡为流程引用；历史未走 OA 的合同需要保留空值或人工备注。
- “到款认领表”的银行流水明细列和“商务签单信息”的商务单明细列是第一期导入契约；后续模板变更须作为版本化的接口变更处理。
- 出账导入字段和模板尚未提供，不能复用到款认领表推断。
- 会议纪要和流程表中的旧状态代码存在语义冲突，因此本模块不复用其 `S001` 至 `S004` 状态定义。
